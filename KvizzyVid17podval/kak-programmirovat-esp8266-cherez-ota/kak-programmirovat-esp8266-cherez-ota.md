## [Как программировать ESP8266 через OTA](#)

Программировать ESP8266 через OTA (Over-the-Air) в PlatformIO действительно можно — это удобно, чтобы обновлять прошивку без физического подключения к компьютеру. 

#### Шаг 1. Настройте поддержку OTA в коде.

Сначала в скетче нужно включить поддержку OTA. В PlatformIO с Arduino Framework для этого используют библиотеку ArduinoOTA. Добавьте в setup() вызов ArduinoOTA.begin(), а в loop() — ArduinoOTA.handle().

Пример:

```
void setup() 
{
  Serial.begin(115200);
  // Подключение к Wi-Fi...
  ArduinoOTA.begin();
}
 
void loop() 
{
  ArduinoOTA.handle(); // Проверяет запрос на обновление
}
```

После загрузки первого скетча через серийный порт в мониторе PlatformIO будет виден IP-адрес ESP8266 — это понадобится для OTA.

#### Шаг 2. Подготовьте разметку флеш-памяти.

Для OTA нужны два раздела во флеш-памяти: активный (откуда запускается устройство) и неактивный (куда пишется новая прошивка). В PlatformIO выбор разметки задаётся через параметр ldscript в platformio.ini.

Найдите подходящий вариант. Список доступных ld-скриптов есть в репозитории esp8266/Arduino (в папке tools/sdk/ld). Выберите тот, под который «влезет» весь ваш код.

Пример строки для platformio.ini:

```
[env:your_env_name]
ldscript = custom_ld_script.ld  ; или выберите из списка
```

#### Шаг 3. Настройте загрузку через OTA.

Теперь можно загружать новую прошивку «по воздуху».

Через интерфейс PlatformIO. В меню задач выберите upload (или uploadfs для файловой системы). Укажите IP-адрес или mDNS-имя (с суффиксом .local) в настройках задачи.

Через CLI. Команда: pio run --target upload --upload_port IP_АДРЕС (или mDNS_NAME.local).

Дополнительные опции. Можно передать флаги в утилиту OTA через upload_flags в platformio.ini. Например:

- --port=8266 — порт ESP8266 (по умолчанию 8266)

- --auth=ваш_пароль — пароль для аутентификации

- --spiffs — чтобы передать образ SPIFFS (файловую систему), а не стирать и записывать новую прошивку

Полный список флагов можно посмотреть, запустив ***espota.py --help***.

Несколько советов:

- Безопасность. Обязательно задайте пароль (--auth), если планируете делиться прошивкой с другими.

- Файловая система. Если вы хотите не только обновить прошивку, но и добавить файлы в файловую систему ESP8266 (например, LittleFS или SPIFFS), используйте ту же логику в коде и опцию --spiffs при задаче загрузки образа.

- Отладка. Если что-то пошло не так, включите подробный вывод: upload_flags = --debug.

После успешной загрузки прошивка начнёт работать, и ESP8266 автоматически перезагрузится.

#### В ESP8266EX WiFi SoC встроен контроллер памяти (SRAM и ROM). 

Микроконтроллер может обращаться к блокам памяти через интерфейсы iBus, dBus и AHB. Все блоки памяти могут быть доступны по запросу, в то время как арбитр памяти будет определять последовательность выполнения в зависимости от времени получения этих запросов процессором.

В соответствии с текущей версией SDK, доступное пользователям пространство SRAM распределяется следующим образом:

- Объем оперативной памяти < 36 КБАЙТ, то есть когда ESP8266EX работает в режиме станции и подключен к маршрутизатору,

- объем программируемого пространства, доступного пользователю в разделе heap и data, составляет около 36 Кбайт.

- В SoC нет программируемого ПЗУ, поэтому пользовательская программа должна храниться во внешней SPI-флэш-памяти.

#### Внешняя SPI-флэш-память

В этот модуль встроен внешний SPI-накопитель объемом 1 МБ для хранения пользовательских программ. Если требуется больше места для хранения, предпочтительнее использовать SPI-накопитель с большим объемом памяти. Теоретически может поддерживаться объем памяти до 16 МБ

#### Рекомендуемый объем SPI-накопителя:

- OTA отключен: минимальный объем поддерживаемой флэш-памяти составляет 512 Кб;

- OTA включен: минимальный объем поддерживаемой флэш-памяти составляет 1 МБ.
Поддерживается несколько режимов SPI, включая стандартный SPI, двойной SPI и четырехъядерный SPI.
